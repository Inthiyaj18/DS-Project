# Mohan Babu University – Data Science Laboratory Portal

A medium-level experiment portal built with **plain HTML, CSS and JavaScript** (no frameworks, no server, no build tools, no environment variables).

The portal is organised into **subjects** — each subject owns its own modules, learning materials and experiments — and ships as one built-in subject, **Data Science**. See [Subjects](#subjects-subject-management-system) to add or switch subjects.

## Run it

**Option 1 – just open it:** double-click `index.html`.

**Option 2 – VS Code (recommended):** open this folder in VS Code, install the *Live Server* extension, right-click `index.html` → *Open with Live Server*.

The **Online Code Lab** (Python sandbox) works either way: over `http://` it runs Python in a Web Worker (recommended, the page stays responsive); on `file://` browsers block workers, so it transparently falls back to the main thread.

## Pages / routes

All navigation uses plain `.html` files with query parameters (no router).

| Page | URL |
|---|---|
| Dashboard (student ID card + learning-suggestion tiles) | `index.html` |
| Subjects (Subject Management System: add/select/edit/delete) | `subjects.html` |
| Experiments (search, experiment cards, **+ Add Experiment**) | `experiments.html` |
| Resources (documentation links) | `resources.html` |
| Student profile (ID card + LinkedIn/GitHub/social links) | `profile.html` (or click the avatar at the top right of any page) |
| Modules list | `modules.html` |
| Module details (study material + PDF) | `module.html?id=1` … `module.html?id=5` |
| Experiment overview (+ files + Code Lab) | `experiment.html?id=06` |
| Sub-experiment (opened from an experiment's **Sub Experiments** panel — no separate sidebar item; includes its own **Online Code Lab**) | `subexperiment.html?experiment=06&sub=6A` |

Every sidebar option opens its **own dedicated page** — nothing scrolls to another section of a different page. Every content page carries the selected subject in `?subject=<id>` (see **Subjects** below). Unknown IDs (`module.html?id=99`, a bad experiment id) render a friendly “not found” page with a link back.

## Things you should edit

1. **Your details** – top of `js/data.js`: `profile` (name, `photo`, roll number, branch, faculty, degree, subject code). The dashboard shows them as an ID card; `profile.html` shows the full profile.
2. **Social links** – `socialLinks` in `js/data.js` drives the buttons on `profile.html` (LinkedIn, GitHub, Instagram, X, YouTube, e-mail). Put your real URLs there; remove a line (or leave it `""`) to hide a button.
3. **Learning suggestions** – `learningSuggestions` in `js/data.js` drives the “Suggestions to learn this subject” tiles on the dashboard (`{ platform, icon, note, url }`). Swap in your own platforms, or delete lines you do not want.
4. **GitHub link** – in `js/data.js`, change `const GH = "https://github.com/";` to your repository URL.
5. **YouTube links** – currently a YouTube search for each topic. Replace with real video links by editing `youtube:` in `buildExperiment` / `buildSub`, or by adding `youtube` fields.
6. **Add experiments** – either use the **+ Add Experiment** button on `experiments.html` (saved in your browser only), the full **Edit Mode** (see below), or add a new block to `experimentConfigs` in `js/data.js` (permanent, visible to everyone).
7. **Modules** – edit `moduleConfigs` in `js/data.js` (title, overview, topics, notes, resources, `pdf`) — or edit/add/reorder modules, swap the PDF and manage materials entirely through **Edit Mode** (see below). Put the actual PDFs at `assets/pdfs/module-1.pdf` … `module-5.pdf`. The page shows a clear “PDF not available yet” message while a file is missing.
8. **Experiment files** – give an experiment a `files` list in `js/data.js`:
   ```js
   files: [
     { name: "NumPy Study Notes.pdf",
       path: "assets/files/experiment-01-numpy-notes.pdf",
       size: "2.7 KB", uploaded: "12 Aug 2025", type: "pdf" }
   ]
   ```
   Save the real file under `assets/files/`. Supported viewer types: `pdf`, `ppt/pptx`, `doc/docx`, `xls/xlsx`, `csv`, `txt/md`, images (`png/jpg/gif/svg/webp`) and `zip`. Anything else (or a missing file) degrades to a friendly message plus a download link — experiments without a `files` list look and behave exactly as before.

   In Edit Mode you do not need to touch `data.js`: every experiment page **and every sub-experiment page** gets a **Files** bar with **+ Upload file** and **+ Add link**. Uploaded bytes go to IndexedDB, the metadata is appended to the experiment's `files` list (or, for a sub-experiment, to the 8th item of its compact tuple — `[name, aim, concept, steps, code, result, insight, files]`) and everything is saved to `mbu-portal-data-v1`, so it survives reloads and shows up for normal users.

## Subjects (Subject Management System)

The portal is organised into **subjects**. Each subject owns its own **modules**, **learning materials** and **experiments** (with their sub-experiments); nothing is shared between subjects. The built-in content ships as one subject — **Data Science** — so the site looks and behaves exactly as before until you add more.

- **Subjects page** (`subjects.html`, sidebar **Subjects**) — a card per subject showing its **module** and **experiment** counts. Cards match the existing module/experiment card style, and the currently selected subject is highlighted.
- **Selecting a subject** — click **Open** on a card (or the **Subject** switcher shown at the top of the Modules, Experiments and detail pages). The choice is remembered and carried through every link, so navigation stays inside the selected subject.
- **Persistence** — the selected subject id is stored in the URL (`?subject=<id>`) *and* in `localStorage["mbu-selected-subject"]`. A direct refresh, a shared link (`modules.html?subject=<id>`), or returning later all load the correct subject. An unknown/deleted id falls back to the first subject instead of erroring.
- **Adding / editing / deleting** — all subject CRUD lives in **Edit Mode** (see below): **+ Add subject** (name + optional description), **✎ edit**, **delete** with a confirmation that spells out the cascade. Duplicate names are rejected. Deleting a subject removes its modules, experiments and custom experiments together — no orphaned records — and the **last remaining subject cannot be deleted**.
- **Auto-association** — a module or experiment created while a subject is selected is automatically tagged with that subject's id; sub-experiments are tagged to their parent experiment. A subject's modules are numbered from `1` and its experiments from `01` **independently** of other subjects, and an experiment created on a module page is linked to that module.
- Every add/edit/delete/reorder/switch re-renders the page immediately (no manual reload), and invalid ids show the usual friendly “not found” page.

### Data model

| Entity | Fields | Notes |
|---|---|---|
| `Subject` | `id`, `name`, `description`, `createdAt`, `updatedAt` | `id` is a generated unique string (`subj-…`), never the name |
| `Module` | `id`, `subjectId`, `title`, `description`, `order`, `createdAt`, `updatedAt`, `materials[]` | `id` is the per-subject module number |
| `LearningMaterial` | `id`, `subjectId`, `moduleId`, `title`, `type`, `fileReference`, `order` | type = `pdf` / `ppt` / `pptx` / notes / other |
| `Experiment` | `id`, `subjectId`, `moduleId?`, …existing fields | `id` is the per-subject experiment number (`01`, `02`, …) |
| `SubExperiment` | `id`, `experimentId`, `title`, `order`, …existing fields | belongs to exactly one experiment |

The model is layered **additively** over the existing store: `mbu-portal-data-v1` now also holds a `subjects` array, and `moduleConfigs` / `experimentConfigs` entries carry a `subjectId`. Browsers that already have edits are migrated automatically on load — existing modules and experiments are assigned to the default **Data Science** subject, so no content is lost. There is no database or framework; lookups are filtered by `subjectId` in `js/common.js`.

## Edit Mode (Admin)

A built-in **Edit Mode** layer lets you edit the portal's content in place — no code, no backend. Everything you change is saved in this browser (`localStorage`) and re-applied over the built-in content on every visit.

**Entering Edit Mode**

> **Note (temporary):** Edit Mode is currently **password-less and open to everyone** — the ✎ button is shown in the top bar and no password is asked. This is controlled by two switches at the top of `js/admin.js`: `REQUIRE_PASSWORD` (set `true` to restore the password gate) and `SHOW_ENTRY_ALWAYS` (set `false` to hide the ✎ button from visitors again). All password code is still present for when you re-enable it.

| Situation | What happens |
|---|---|
| **Every time** | Click the **✎** button in the top bar, press **Ctrl + Shift + E** anywhere, or append **`?admin=1`** to a page URL (e.g. `experiment.html?id=01&admin=1`) — Edit Mode turns on immediately. |
| **Leaving** | **Ctrl + Shift + E** again, the **Exit** button in the floating toolbar, or the ✎ button in the top bar. |

When `REQUIRE_PASSWORD` is set back to `true`, first-time users get a **Create admin password** dialog (choose your own, min 4 characters, saved in `localStorage["mbu-admin-pass"]`), returning users sign in with it, and the **Password** button appears in the toolbar to change it.

**What you can do while it is on**

- A floating **Edit Mode toolbar** appears (badge + **Export** / **Import** / **Reset all** / **Exit**; a **Password** button appears too when the password gate is enabled). Export downloads a `mbu-portal-data.json` backup; Import restores one; Reset all asks for confirmation, then returns every edit to the built-in defaults.
- **Subjects page** – add a subject (name + optional description), **edit** it, or **delete** it (the confirmation explains that its modules, experiments and sub-experiments are removed too; the last subject cannot be deleted). Duplicate names are refused. A module/experiment added while a subject is selected is tagged to that subject automatically.
- **Dashboard** – edit the student **ID card** (name, photo, roll number, branch, faculty, degree, subject code) and the **Suggestions to learn** tiles (one tile per line: `icon | Platform | URL | note`).
- **Profile page** – edit the same ID-card details and the **Connect** links (LinkedIn, GitHub, Instagram, X, YouTube, email, website — clear a field to hide that tile).
- **Experiments page** – ✎ edit an experiment's name/description in place, **+ Add experiment**, delete (with *Are you sure…?* confirmation) and reorder (↑/↓ with a confirmation explaining the renumbering).
- **Experiment page** – edit title, overview, aim, problem statement, analysis, results inline (each field gets **Save**/**Cancel**; Cancel restores the original), edit the dataset (form dialog), edit the methodology/architecture as line lists, manage sub-experiments (add/rename/move/delete, last one cannot be deleted) and manage the Experiment Files list (**upload a file** — stored in this browser's IndexedDB — or **add by URL**, edit, remove).
- **Sub-experiment page** – edit the aim/concept/steps/result/analysis panels inline, edit the lab **code** with a dedicated editor (**Edit / Copy / Reset-to-saved / Cancel / Save**, Tab inserts 4 spaces, Ctrl+Enter saves), add/move/rename/delete sub-experiment tabs, and manage that sub-experiment's own **Experiment Files** list (upload a file or add by URL, edit, remove — the panel is hidden on the public page until at least one file exists).
- **Modules pages** – add/edit/delete/reorder modules (each new module belongs to the subject you are viewing); on a module page edit the title/overview/topics/concepts/notes/resources/diagrams, **replace the PDF** (upload or URL, or remove it) and manage **materials** (add a link or upload a PDF/PPT/PPTX/DOC/… , edit, reorder with ↑/↓, remove — each remove asks for confirmation).
- Every delete is guarded by a confirmation dialog (*Cancel* / *Delete*); nothing is removed by a single stray click.

**Storage** – edits live under the existing key `mbu-portal-data-v1` (`subjects` + `experimentConfigs` + `moduleConfigs`); uploaded files live in IndexedDB `mbu-portal-files` and are referenced as `mbu-blob:<id>` URLs. The Edit Mode *session* itself (so the toolbar survives navigation) is kept in `sessionStorage` for the tab only. The currently selected subject is kept in `localStorage["mbu-selected-subject"]` and in each page's `?subject=<id>` query parameter.

## PDF viewer — Normal / Book view

On a module page the PDF opens in the **existing scrolling Normal view**. Under the viewer there is a small toggle:

- **[Normal View]** – the original embedded scroll view, unchanged.
- **[Book View]** – a full-screen flip view: **← / → Previous/Next page**, page-flip animation, **zoom − / +**, a *page x / y* indicator, and **Normal View** (or ✕ / Esc) to go back — the page you were on is remembered per PDF, in both directions.

Other file types (PPT/PPTX, DOC, images, ZIP, notebooks, …) keep their existing preview behaviour.

## Online Code Lab (Python sandbox)

- Python runs **entirely in your browser** with [Pyodide 0.29.5](https://pyodide.org/) (WebAssembly) inside a **Web Worker** — nothing is uploaded, no backend, no API key.
- The first run downloads Python and the libraries your program imports (then it is cached); the status line shows progress (`Loading numpy, pandas…`, `Installing seaborn…`).
- Libraries: everything in the Pyodide build (`numpy`, `pandas`, `matplotlib`, `scipy`, `scikit-learn`, `scikit-image`, `statsmodels`, `sympy`, `networkx`, `pyarrow`, `xgboost`, standard-library modules, …) **plus `seaborn`, `openpyxl` and `plotly`**, which are installed from PyPI with `micropip`. `polars` is **not** available in this Pyodide build (it ships compiled Rust wheels), so `import polars` shows the clear "not available" message plus the list of supported libraries — nothing fails silently.
- **Ordered, structured output** (`js/pycode.js` + `js/compiler.js`): every run returns a list of outputs in execution order — `text`, `dataframe`, `image`, `plotly`/`altair`/`bokeh` and `error` — and the page renders them under the editor in that exact order. Several outputs from one program (prints, tables and charts mixed) all appear, and a chart is never lost when execution ends.
- **Interactive DataFrames:** `display(df)` **and** `print(df)` render a real table — column headers with dtypes, the row index, right-aligned numbers, `—` for missing values, row/column count, **search**, **sort** (click any header), **pagination** (50 rows per page) and a **Download CSV** button. Wide tables scroll horizontally. The screen shows the first 500 rows of large frames (the count still reports the full shape, e.g. `5000 rows × 1 cols`).
- **NumPy and other values:** arrays/statistics print as readable text; the last expression of the program is shown Jupyter-style. Charts have a **Download PNG** button.
- **Charts — detected automatically from your code:** matplotlib/seaborn figures render as PNGs (`plt.show()` and figures left unshown are both captured), **plotly** figures (`fig.show()`) as interactive charts (plotly.js CDN), **altair** charts as Vega-Lite embeds and **bokeh** figures via BokehJS. There is no chart selector to configure — just write the plotting code and press Run.
- **Seaborn `sns.load_dataset(...)` works offline.** This sandbox is Pyodide, which has **no `ssl` module**, so the standard `urllib.request` cannot open `https://` URLs (that is the cause of `urllib.error.URLError: <urlopen error unknown url type: https>`). `js/pycode.js` now bridges `urllib.request.urlopen`/`urlretrieve` onto Pyodide's own HTTP client (the browser's real, certificate-checked HTTPS fetch — no insecure workarounds), and answers seaborn's dataset URLs from a **genuine bundled copy first**:
  - **Bundled & offline (no network at all):** `tips`, `iris`, `penguins`, `titanic`, `flights`, `exercise`, `fmri`, `planets`, `dots`, `mpg`, `dowjones`, `car_crashes`, `attention`, `anagrams`, `anscombe`, `geyser`, `glue`, `healthexp`.
  - **Bundled, served on demand:** `diamonds`, `seaice`, `taxis`, `brain_networks` (in `assets/datasets/`, fetched from this site — no external network).
  - **Any other name** is fetched securely over HTTPS from `mwaskom/seaborn-data` when you have internet; if it cannot be loaded you get a **clear error listing the available datasets** — no fabricated data is ever returned.
  - The CSVs are unmodified copies of the official [mwaskom/seaborn-data](https://github.com/mwaskom/seaborn-data) repo (BSD-3-Clause); `tools/build_datasets.py` regenerates them.
- **Notebook-like controls:** ▶ **Run**, ■ **Stop** (kills an infinite/long-running program), ⟳ **Restart** (fresh Python runtime) and **Clear output**, plus the execution status and elapsed time. Variables do not persist between runs (each Run is a fresh program), so Restart simply gives you a clean runtime.
- **Merged terminal (VS Code style):** output and input live in **one panel** — the `›` prompt line sits at the bottom of the terminal, so input can be typed right where the program prints. Typed input is echoed into the scrollback (like a real terminal) when you press Run; stdin is still collected before the run (a program that asks for more input than provided ends with an `EOFError` traceback — add the value and Run again).
- **Smart editing:** the CodeMirror editor auto-closes brackets and quotes — type `(` and it inserts `()`, and typing `"` or `'` pairs them. Brackets are also matched/highlighted.
- Limits: 90 s to prepare (downloads), 30 s per program run. The Python sandbox cannot read files on your computer; it can use the datasets bundled with the site and, when online, fetch data over HTTPS through the browser.
- If the sandbox cannot start (workers blocked, CDN unreachable), Python falls back to the existing online [Judge0](https://ce.judge0.com/) compiler — unchanged behaviour, but Judge0 has **no** data-science libraries and cannot read the bundled datasets.
- The editor is CodeMirror 5 (cdnjs). Without internet it degrades to a plain textarea; everything else keeps working.
- The Code Lab appears on the experiment page **and on every sub-experiment page** (`subexperiment.html`), preloaded with that sub-experiment's code (tab switches refresh it unless you have edited the editor; **Reset** brings the sub-experiment code back). The section markup and the CodeMirror script block are **mirrored in `experiment.html` and `subexperiment.html`** — if you change the Code Lab layout, apply the same change to both files.

## Notes

- **Storage (all per browser, no server):**
  - `localStorage["mbu-portal-data-v1"]` – the merged content state: `subjects` + `experimentConfigs` + `moduleConfigs` (Edit Mode edits, “+ Add Experiment”, subjects, everything). Remove this key (or use **Reset all** in Edit Mode) to return to the built-in content.
  - `localStorage["mbu-selected-subject"]` – the id of the currently selected subject (also carried per link/page as `?subject=<id>`); used to restore the selection on your next visit.
  - `localStorage["mbu-theme"]`, `localStorage["mbu-custom-experiments"]` – dark/light choice and the original “+ Add Experiment” list (unchanged).
  - `IndexedDB["mbu-portal-files"]` – files uploaded through Edit Mode (materials / experiment files / module PDFs), referenced as `mbu-blob:<id>`.
  - `localStorage["mbu-admin-pass"]` – the admin password (only used when the password gate is enabled; currently Edit Mode is password-less, so this is unused).
  - `sessionStorage["mbu-admin-session"]` – keeps Edit Mode on while you move between pages; cleared when the tab closes or you press Exit.
  - **Export / Import** in the Edit Mode toolbar moves all of this between browsers as one `mbu-portal-data.json` file.
- **Imported notebooks:** the lab record's Jupyter notebooks were imported into `assets/files/imported/` and linked automatically — as materials on experiments 01–04 and as sub-experiment tabs (e.g. `subexperiment.html?experiment=04&sub=4N`). To re-import after changing the notebooks, run `python import_notebooks.py` from the project root (`MBU-DS-pro/`; needs the `nbformat` package).
- The Seaborn example datasets are **bundled with the site** (`assets/datasets/` + `js/datasets.js`), so `sns.load_dataset("tips"/"iris"/"penguins"/"titanic")` and the other bundled names work with **no internet at execution time**. Refreshing them (`python tools/build_datasets.py`) does need internet.
- Internet is only needed for: the CDNs (CodeMirror + plotly.js on cdnjs/plot.ly, Pyodide on jsdelivr, **pdf.js 3.11.174 on cdnjs — only when you use the PDF Book view**, vega/vega-lite/vega-embed on jsdelivr for altair, `@bokeh/bokehjs@3.6.3` on jsdelivr for bokeh), PyPI wheels (`seaborn`, `openpyxl`, `plotly`), non-bundled `sns.load_dataset` names and Judge0 — the pages, styles, content, PDFs and the bundled datasets are all local.
- Connecting a Jupyter kernel running on your machine was deliberately **not** done: a static page cannot talk to it without a helper server (CORS/auth), and any website could then execute code on your kernel. The built-in sandbox gives the same notebook feel offline instead.
